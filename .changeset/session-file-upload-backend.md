**Drop any file into a session, not just an image.** `POST /api/sessions/:id/upload-file` takes a pdf, csv, zip or log and stores it under `{workingDir}/.claude-files/` for the agent in that session to read. It is a sibling of `paste-image`, not a second upload stack: the CSRF gate, the 30 uploads/min per-(IP, session) bucket, the ownership lookup and the symlink-safe directory creation are now three shared functions both routes call, so the checks have one implementation rather than two that drift. What stayed apart is what actually differs — an image is magic-sniffed, HEIC-converted and machine-named because we serve those bytes back with an `image/*` MIME; an uploaded file is stored verbatim, because nothing serves it and guessing what a `.zip` "really is" would only reject honest files.

The name a client sends is treated as hostile input, not as a filename. `sanitizeUploadFilename()` keeps the last path segment (`../../etc/passwd` → `passwd`, `C:\windows\x.dll` → `x.dll`), deletes zero-width and bidi-override codepoints (`report\u202Egnp.exe` renders as `reportexe.png` in any picker), and reduces the rest to an allowlist of letters, digits, `.`, `_` and `-` — an allowlist because the saved path is inserted into the terminal for the agent to act on, so `notes;rm -rf ~.txt` must not arrive at a prompt as two words. Non-ASCII letters survive (`Angebot-Jänner.pdf`, `报告.csv`): no UTF-8 byte of theirs can collide with an ASCII metacharacter. Leading dots and dashes go (no hidden files, no path that reads as an option), and the name is capped at 100 chars with the extension preserved.

Nothing is ever overwritten. The write walks `report.pdf`, `report-1.pdf`, `report-2.pdf` … and each candidate is attempted with `O_EXCL|O_NOFOLLOW` and mode `0644`, so the open IS the collision check (no stat-then-open window), a planted symlink is refused rather than written through, and the file can never be executable. `MAX_UPLOAD_FILE_BYTES` defaults to 25MB — half the image cap, applied as a per-request busboy limit so an oversized body is aborted mid-stream instead of buffered and then measured.

Also fixed on the way through: both upload routes now refuse a **remote (SSH) session** with a clear message. Such a session's `workingDir` is a path on the other host — for an attach it is the relative pseudo-path `user@host:name` — so `paste-image` used to `join()` it under the server's own cwd and report success for a file the remote agent could never open. Docker sessions are unaffected and correct: their `workingDir` is the host side of the case's bind mount.
